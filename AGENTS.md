# Project documentation

Describe independently verified software behavior, implementation and test
results in public project text. Keep private discussions, participant identities,
communication excerpts, paraphrased comments and report inventories in private
tracking. This applies to documentation, README files, release notes and review
or issue prose. Preserve private acceptance criteria when removing older records;
do not restore those records from historical branches.

Concise QA credits are permitted; keep them separate from private communications.
