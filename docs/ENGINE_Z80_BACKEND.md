Fresh due diligence overturned the earlier "already native" disposition.

## Delivered contract

The shared default-OFF CMake helper integrates the real generated flat-step
source and adapter in both supported runner targets and legacy consumers via
the deferred reconciler. It validates source/core/entry and is idempotent.
Explicit GameSpec hooks take precedence; NULL hooks use the configured entry.
The conflicting SMS function-form call ABI is excluded. The option remains
OFF by default; this does not deploy a driver catalog or semantic sound HLE.

The cartridge adapter owns the existing bounded native scanline interval.
It keeps per-instruction live guards, original cycle-start audio stamps,
bus effects and IRQ slots. Legacy registers/flags materialize before fallback
and at the slice edge. Traced builds retain per-step publication to preserve
bus trace observations. The independent one-step API remains. CD already
has native continuous intervals; reuse is not a new performance claim.

Five cartridge boundary defects were reproduced before repair: HALT omitted
R refresh; ordinary and prefixed fallback EI accepted pending IRQ too early;
IRQ changed PC without WZ; fallback discarded native64-bit cycle history
through Windows32-bit unsigned long. These are five recorded failing modes
(EI and prefixed EI exercise the same cause). Related CD IRQ acceptance also
omitted WZ. The real SMS/GG producer's live absolute/indexed operand handlers
omitted WZ; `LD (nn),A` reproduces PC000b WZ0000/a501. Each fix preserves the
actual interpreter's architectural contract; no semantic handwritten driver
replacement or title-PC check was added.

## Independent qualification

`tests/z80_adapter` links the actual adapter, SuperZazu and real generated
fixtures, using the shared CMake helper with a NULL GameSpec entry. Eleven
tests pass on MSVC19.44 and GCC13.3, including full state and RAM, refresh
wrap, IM1/IM2, pending EI/HALT boundaries, reset and cycle rollover.

The synthetic64-byte variant fixture is generated by the actual isolated
SmsRecomp producer. It covers256 live immediate/displacement values, four
absolute forms, both captured INC/DEC alternatives, unknown opcode fallback,
partial uploads and native resumption. Inputs, command, producer commit,
executable SHA and normalized generated-file SHAs are committed alongside it.
Generation requires an explicit producer commit; arbitrary binaries are not
silently attributed to an old source. No game bytes are committed.

The ordinary and traced slice tests each compare1032 paired configurations
against the retained per-step contract, checking full architecture/legacy
state, RAM, debt, timed bus operations, IRQ asserted from a bus callback and
fallback counts. Real CD machine tests additionally write actual BUSREQ/reset
MMIO while a continuous Z80 interval is active at1/2/7/31 prior steps. Both
run styles retire the exact current-instruction prefix, then hold/reset.
CD IM1/IM2 assertions check PC/WZ/stack/cycles. The two affected CD test targets
pass on both compilers. These are behavioral checks, not source-shape tests.

## Built consumer evidence

The frozen supported RKA and Sonic1 consumers build with the default path and
with native Z80 enabled, proving actual deferred reconciliation and legacy
header/entry integration. Native sources are private mechanically generated
inputs extracted from the prior task's disposable state captures; all runtime
arms boot fresh and retain live guards. No older state is loaded into another
build. Captures, producer and generated identities are retained in the build
receipt. Native-step and native-slice use the same new boundary/generator
fixes; their A/B comparison isolates publication consolidation.

RKA6000-frame and Sonic1 2400-frame accepted gameplay routes run in isolated
profiles with faithful audio, dummy SDL output and full WAV capture. Each game
has A/D/D/A (frozen E05/default) and S/N/N/S (native step/slice) samples.
All16 runs pass: complete game state matches within each matched package,
and frame checkpoints, pixels, full WAV and audio counts match across all
packages. Rollback passes with zero divergences/asymmetries. Both native-slice
builds save/load their own current-build file, restore exact RAM, make progress
and match the existing lifecycle framebuffer/RAM evidence.

All runtime performance is **neutral/inconclusive**. RKA slice CPU reductions
are+15.36/-9.53percent with native-step A/A drift-34.72percent; Sonic1 gives
-0.57/+19.43percent with+41.95percent drift. Process-cycle results are similarly
mixed within the observed variation. Default-vs-E05 results likewise have
large drift. Do not quote the favorable pairs as proven gains, or combine
default/native and native-step/slice as one optimization package. Native
driver rollout remains outside this engine task and the default stays OFF.

The final CD IRQ-WZ build passes a matched3000-frame A/B route: full memory,
checkpoint CPU/device observations, pixels and full WAV match the frozen
E05 build; native instruction totals are unchanged and floor/audio faults
remain zero. Its single-pair CPU/cycle reductions14.69/17.80percent are
inconclusive without an A/A variation control; no speedup is claimed.

All nine original CD Z80 images were regenerated through the supported helper
with the fixed producer. They produce a byte-identical module: the repaired
live-operand paths are not selected by those particular variant combinations.
The tested CD binary therefore already contains the final code; no archive
member replacement or repeated game run is needed. The old-source and new
generator manifests and module hashes are retained. No claim that the full
Z80 ISA or all future driver combinations have been exhaustively certified.

Native-slice adds512 bytes over native-step for RKA and zero for Sonic1;
default executable deltas versus E05 are0/512 bytes. Native generation itself
adds about1.64MiB RKA/1.57MiB Sonic1 relative to the default builds. Those are
separate package costs, not the slice increment. Built RSS/startup-memory
deltas were not measured and are not claimed zero.
