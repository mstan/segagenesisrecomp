# E16 shared final pixels and upload ownership

The candidate consolidates indexed conversion, raw/color/UI staging and upload preparation across the engine and both presentation frontends. Actual color-enabled RKA and Sonic 1 runs used substantially less CPU. Raw/default results and Sonic CD are neutral/inconclusive; all adverse CD observations remain in the record. Fresh independent final review is pending, so E16 remains open until that gate completes.

The machine can deliver current indexed rows and a fresh palette directly into the shared runner's owned raw destination, avoiding an intermediate ARGB row and copy. The additive sink adapter preserves the original hook layout and caller context; custom, declined, null and legacy producers retain the old route. Guest execution, timed palette reads, sprite/status evaluation, interlace ordering and overlays continue. The exact finite inverse-DAC table removes three repeated nearest-value searches from each color-transformed pixel. Arbitrary RGB/alpha behavior and the general uint32 helper retain their original semantics.

A shared synchronous frame view either borrows immutable raw storage or uses caller-owned writable staging. Color transforms affect the active extent; UI-only copies preserve full storage and filter-padding history. It rejects overflow, inadequate capacity, invalid pitch and aliases against the full declared raw storage, including inactive rows. Main and CD use the same ownership contract. CD closed/aligned UI presentation can upload borrowed raw pixels; open UI or odd byte pitch uses owned packed staging. No borrowed pointer outlives the call, and raw hashes/captures stay independent of presentation. Upload rectangles, full-texture linear filtering, peer crop and the existing backend remain intact. `GENESIS_FINAL_PIXEL_PIPELINE=0` retains the portable original implementation under the same interface; no assembly or new platform dependency is introduced.
