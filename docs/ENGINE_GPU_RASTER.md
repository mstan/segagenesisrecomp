# E17 optional GPU raster evaluation

Both complete optional raw GPU architectures were implemented and reached actual native gameplay. The proposed bounded disposition is rejection: expanded packets have no proven useful gain, while compact pattern packets repeatedly worsen RKA frame completion and cycle costs. The CPU implementation is restored byte-exact to the accepted E16 base, including all build/test wiring. Independent final review is pending; E17 and18 original families remain open until that gate. No optimization is adopted, no PR is needed for discarded infrastructure, and no claim excludes every possible future GPU algorithm.

Expanded packets preserve CPU sprite/status evaluation and move final plane/sprite priority and DAC composition to hardware. Compact packets additionally move background pattern decode to hardware, carrying exact pattern words/maps; sprites remain CPU-decoded during mandatory hardware status evaluation. Both own immutable row palettes, window/scroll/interlace geometry and raw history. The integrated optional GL3.3 backend writes an SDL texture directly, resolves canonical raw pixels only for readers, and crosses the thumbnail subsystem boundary through lazy last-presented-frame ownership. No per-title renderer adapter or required extra frame of latency was added. Default CPU, custom/private renderers, color/UI and unsupported hosts retain the original CPU route.

The initial two alternatives paid full GPU preview readbacks during rewind cadence. After those unsuccessful experiments, a coherent second implementation uses exact packet sampling immediately after publication and bounded old-texture readback after another frame begins. Source serials prevent new packets from impersonating the previous presented image. Actual R2 gameplay reports zero preview readbacks, with1007 RKA and412 Sonic1 thumbnail consumers. That fixes the large initial cost, but establishes no useful current gain.
